# Games Widget 2.3.4

- **Strict grid alignment (vertical perf)**: CPU/GPU/RAM rows are back on a fixed 5-column CSS Grid (`label | ring | value | ring | value`) with pixel-locked columns — both rings and both readouts hold identical X positions across all rows, values sit directly adjacent to their rings, and wide strings like `11.4 GB` fit without clipping.
- **Wider RAM container (horizontal perf)**: The stats grid now uses uneven tracks — FPS `1.1fr`, CPU `1fr`, GPU `1fr`, RAM `1.5fr` — so the RAM card is noticeably wider to comfortably fit `11.4 GB` plus its percentage, while CPU/GPU stay compact and uniform.
- **Tighter horizontal overlay**: Window resized to 500×56px; panel/control gaps and card padding reduced for a cleaner FPS-overlay footprint.
- **Fixed-column metric grid (horizontal)**: CPU/GPU/RAM rows use the same strict column pattern as the vertical view (`icon | ring | value | ring | value`), giving uniform element-to-element spacing; metric cards are content-sized so each ends just after its last readout.
- **Text-only overlay controls**: The horizontal layout toggle, minimize, and exit controls are now chromeless text glyphs (`≡`, `−`, `×`) that light up green/yellow/red on hover — no button boxes, enabling the slimmer 56px height.
- **Vertical ring shift**: Metric columns widened slightly so both rings move right and the trailing percentage ends flush with the card's right edge.
- **Bolder overlay glyphs & RAM spacing**: The `−` and `×` text controls are heavier weight; the first value column in horizontal rows widened to 34px so `11.4 GB` gets breathing room before the second ring.
- **Vertical pair refinement**: Rows use flex spacing — the first ring+value pair shifts slightly right of the label, and the second pair stays glued together pinned to the right edge with the percentage flush against the container edge; ring 2 keeps a consistent X position via a fixed min-width on the first metric.
- **Snug horizontal metric cards**: Value columns tightened to 32px/26px so each card ends just after its last readout with only ~2px of padding, uniformly across CPU/GPU/RAM.
- **Uniform ring↔number spacing**: Horizontal metric columns switched to `max-content` so every readout sits the same 2px from its gauge in all three containers; vertical rows fixed so the second ring sits a uniform 6px from its percentage and the `%` keeps 10px of right padding.
- **Perf header top padding**: The vertical performance header gets 6px of top padding so the layout/minimize/exit controls no longer hug the window frame.
- **FPS card & metric card sizing**: The horizontal FPS card is pinned to a fixed 130px track (restoring its previous footprint), and CPU/GPU/RAM cards get slightly more padding (4px) for a bit more presence.
- **Vertical perf rows back on strict grid**: Removed the flexbox experiment — rows again use fixed columns (`36px | 22px | 58px | 22px | flexible`) so ring/readout X-positions can never shift when a value changes width (e.g. GPU load dropping to a single digit `5%`). Ring↔number gaps are uniform and the last column absorbs slack as right padding.
- **Horizontal density pass**: Metric card padding 4px→5px horizontal, row column-gap 2px→3px, row min-height 22→24px; window widened 500→545px to fit the roomier cards with no trailing dead space.
- **Fixed-width metric columns**: Horizontal metric rows switched from `max-content` to fixed columns (`18px | 10px | 36px | 10px | 32px`) so CPU/GPU/RAM cards can never shrink or shift when a value drops to a single digit; window width set to 568px for an exact fit. Metrics remain left-aligned so every number sits a constant gap from its ring — right-alignment was tried and rejected because it pushed single-digit values away from their gauges. Last value columns tightened (vertical `1fr`→`46px`, horizontal `32px`→`28px`) so numbers sit close to the card edge; horizontal window 568→555px.
- **User-tuned compact layout**: Horizontal bar reworked to the user's hand-tuned proportions — window 528px, CPU/GPU cards fixed at 107px, RAM at 115px, denser row columns (`14px | 10px | 32px | 10px | 24px`), baseline-aligned units for cleaner symbol positioning, and normalized control glyph sizing/spacing. Vertical perf window resized to 232×264 (links variant 308px) with tightened grid columns (`34px | 22px | 56px | 22px | 46px`).
- **Second user-tuned pass**: Vertical window shrunk to 216×264 with smaller rings (18px), values (16px), and grid columns (`30px | 18px | 52px | 18px | 44px`). Horizontal bar tightened further — window 528×52, all metric cards ~100px (RAM 104px for `11.4 GB`), compact row columns, and control glyphs reduced to 12–13px with zero padding so the button stack fits the slimmer 52px height.
- **User overrides applied verbatim**: The layout-editor overrides were converted directly into CSS — horizontal window 512×50, vertical 213×265, metric cards fixed at 100×40px with the user's exact translate offsets (GPU −7px, RAM −14px), and per-element nudges on the second ring/value/unit of the GPU and RAM rows reproduced as transform rules. Control glyphs normalized to 12px for even spacing.
- **Override correction pass**: Fixed an off-by-one in row targeting — the editor's `nth-of-type(2/3/4)` map to CPU/GPU/RAM respectively, so the −8px ring/value nudges now apply to CPU and −7px to GPU (RAM had none). Card translates replaced by a uniform 2px stats gap matching the user's final drag positions; vertical window tightened to 204×265 with 16px rings and `28px | 16px | 50px | 16px | 40px` columns; dev shim no longer blocks container resizing with `!important`.
